# Legacy inverse characterization v1

Run `python3 characterization/inverse-v1/run.py --output /absolute/evidence/path` from the canonical Matrix checkout. The runner verifies the seven source hashes in multiplication-v1/sources.json, compiles each legacy definition separately (Neuro C++17, Bitmap C++20), and runs Debug, Release with NDEBUG, and ASan+UBSan. No legacy or consumer source changes are required.

Each executable has 49 active checks: float/double/int empty and scalar inverses, analytic 2x2 and unimodular 3x3 references, const-input preservation, independent result storage, negative determinant, nonsquare rejection and preservation; float/double singular rejection and preservation, small nonzero determinant rejection, and nextafter/exact/negative threshold boundaries; five negative/positive controls for the finite comparison helper. Fixtures use bounded integer arithmetic and analytic expected entries, without using matrix multiplication or determinant to compute the expected inverse.

The ordinary suite avoids integer singular inversion. Two separate nonrecovering UBSan probes characterize that path: Neuro is expected to fail with division-by-zero diagnostics; Bitmap must throw runtime_error with clean stderr. A diagnostic failure documents a legacy defect, not an acceptable future error contract. The integer reciprocal is computed before multiplying cofactors, so non-unit integer determinants yield zero entries, rather than a rational inverse. Unimodular integer matrices remain meaningful.

Neuro compares against T(1e-9); Bitmap compares against double 1e-9. On the qualified Linux platform the exact float representation is below the double threshold: Neuro accepts it and Bitmap rejects it. Both reject small nonzero determinants. A reviewed safe integer-singular policy and explicit floating threshold adapter decision are required before extraction.

This bounded harness does not qualify nonfinite inputs, INT_MIN/overflow, large-dimensional inverse limits, ill-conditioned error bounds, nondefault empty shapes, actual Pixel, allocation failures, saved-model serialization, Windows/MSVC, full CI, package extraction/version acceptance or downstream migration. Strict Neuro C++20 remains independently open. Existing Neuro and Bitmap owners retain migrations. Scoped branch publication and a draft PR were authorized on November 1, 2026; independent technical review and package/consumer acceptance remain open.
